# Recipe Deck

レシピ本文・10点評価・最大3つのタグ・ジャンル・備考を保存する個人用PWAです。端末内のIndexedDBへ保存し、専用アドレスで接続すると変更分を自動でクラウドへバックアップします。

クラウド対応版: https://recipe-deck-backups.dengana-10011212.workers.dev/
従来版: https://yuuuh26.github.io/recipe-deck/

## 自動クラウド保存

v1.4.0ではレシピごとにジャンルを1つ選べます。初期候補は「鍋・炒め物・パスタ」、任意のジャンルも編集画面や設定で追加できます。一覧のキーワード・評価・タグ・ジャンル検索は、初期状態では閉じた「検索・絞り込み」にまとまり、条件をANDで組み合わせます。閉じても絞り込み条件を表示し、条件を一括解除できます。出力画面の条件指定も折りたたみ式です。以前のレシピやバックアップはジャンル未設定として引き続き利用できます。ジャンルはAI出力・完全バックアップ・クラウドバックアップにも含まれ、ジャンルだけの変更や候補の追加・削除も自動保存対象です。

- 初回は設定で、レシピ専用の復旧キーと端末名を入力して接続します。復旧キーはブラウザーやコードに保存しません。
- レシピの追加・削除、本文・備考・評価・タグの変更、タグの追加・削除、完全バックアップのインポートが対象です。本文・備考の追加・削除・書き換えは前回の送信から累計10文字で、編集が止まって約3秒後に送ります（Unicodeコードポイント単位、1回の保存につき各欄は最大10文字まで数えます）。10文字未満でも1分間編集しないとき、または編集画面を離れると送ります。タグ・評価の変更、削除、インポート・復元は文字数に関係なく約3秒後に送ります。閲覧・検索・料理モード・AI用出力・ファイル保存日時の記録は送信しません。
- 未送信の変更番号・文字数・最後の編集時刻と送信中のスナップショットはIndexedDBに保持します。文字数の判定や状態表示ではレシピ全件を読み込まず、送信が必要なときにだけ全件を読み込みます。オフラインや通信失敗時は端末データを保持し、再接続・再起動後に再送します。応答が消失した場合も同じID・内容を再送し、履歴の重複を防ぎます。送信中の変更は次の送信に残ります。
- 前回の成功日時は、サーバー保存後の読み戻し照合まで完了した時に記録します。
- レシピ専用Worker・D1・復旧キー・Cookieを使用します。カラオケアプリとは独立しています。通行証はホスト限定のSecure/HttpOnly/SameSite=Strict Cookieで保持し、サーバーではハッシュだけ保存します。サーバーによる有効期限は設けず、各操作で解除済みか検証します。ブラウザーのCookie保存期限やサイトデータ削除によって再接続が必要になる場合があります。
- 設定の「接続中の端末を管理」は復旧キーで本人確認し、個別・全端末の接続を解除できます。復旧キー自体を盗まれた場合は、端末解除に加えてWorkerのキーを変更してください。
- 全端末共通で最新5世代を保持します。新しいバックアップをD1から読み戻し、形式・件数・SHA-256を確認してから、世代番号の付与と古い履歴の削除を1トランザクションで実行します。失敗時は旧5世代と未確認の新規データを保持します。
- バックアップは平文で保管します。認証された端末から読み出せます。自動バックアップは双方向同期ではありません。他の端末のレシピは、設定で履歴を確認・復元して取り込みます。
- クラウドからの復元は内容確認と明示確認を経て実行し、現在の端末データを同じトランザクションで退避します。同時に編集されていた場合は中断します。退避データは設定から完全バックアップJSONとして保存できます。
- クラウド用スナップショットは8MBまでです。上限超過時も端末データを保持します。

## 任意の手動バックアップ

クラウド接続中はレシピの変更を自動保存するため、以前の「10件追加ごとの手動バックアップ通知」は廃止しました。端末への完全バックアップJSONの保存・インポート機能は引き続き使用できます。JSONの保存はボタン1回で開始し、保存後の件数リセットや確認操作は必要ありません。古いJSONファイルの復元互換性は維持しています。

## 従来版から移行

1. 従来版の「出力」で**完全バックアップJSON**を保存します。AI用JSONは復元用ではありません。
2. クラウド対応版を開き、設定でレシピ専用の復旧キーを入力して接続します。
3. 「出力」でJSONをインポートします。検証・確認後に端末データを取り込み、自動でクラウドへ保存します。
4. 設定で前回のクラウド保存日時を確認してください。従来版の端末データは従来のアドレスに残ります。

端末やブラウザーの保存領域を削除すると、未送信の変更が失われます。完全バックアップJSONの保存も利用できます。初回読み込み後はオフラインでも編集できます。

## 開発・デプロイ

`npm ci`、`npm test`、`npm run build:worker`。ローカル表示はHTTPサーバーで配信します。

`cloudflare/migrations/` を専用D1へ適用し、`cloudflare/dist/site-worker.js` をWorkerへアップロードします。`DB`を専用D1に紐付け、`BACKUP_TOKEN_SHA256` にレシピ専用復旧キーのSHA-256をSecretとして設定します。復旧キー原文をリポジトリ・フロントエンド・ログに含めないでください。再デプロイ時はSecretを保持します。

Service Workerは公開アセットだけキャッシュします。`/v1/` の認証・履歴・復元データはキャッシュしません。

## ChatGPTから新しいレシピを受信（v1.5.0）

MCP接続先は `https://recipe-deck-backups.dengana-10011212.workers.dev/mcp`。ChatGPTのカスタムMCP追加でOAuthを選びます。許可するのは `create_recipe_draft`（新しい下書きの追加）のみで、既存レシピやバックアップを読む・変更するツールは公開しません。OpenAI APIキーもCloudflare管理トークンも不要です。

ChatGPTに「このレシピをRecipe Deckへ送って」と頼むと、送信後にアプリを開いたとき・画面に戻ったときに、確認画面なしでレシピ一覧へ自動追加します。ホームが開いていれば本文も表示します。別のレシピを編集中なら、その本文は保ったまま一覧に追加します。複数件もまとめて追加し、通常の自動クラウド保存と完全バックアップに含めます。旧版で確認中だった下書きは端末での編集内容を引き継いで追加します。同じ送信の再受信・複数タブで重複登録せず、受信通知に失敗しても削除したレシピを復活させません。起動・画面復帰・オンライン復帰・手動受信時だけ確認し、定期ポーリングは行いません。

認証は `@cloudflare/workers-oauth-provider` 1.2.3を固定使用。公式ライブラリのKV互換ストアを専用D1テーブルへ接続し、既存Worker/D1/復旧キーを維持します。PKCE S256、期限付きトークン（アクセス1時間・接続最大30日）、送信回数と本文サイズの制限を使用します。OAuth接続先はChatGPTのHTTPSホストに限定します。公開コード・URL・ログへ秘密を入れません。トークンで既存バックアップAPIにはアクセスできません。

設定の「ChatGPTとのレシピ連携」から受信確認・MCP URLコピー・AI接続の全解除ができます。解除には端末管理欄の本人確認用復旧キーが必要です。アプリの端末ログアウトとAI接続の解除は別です。

デプロイ前に `0004_mcp_drafts.sql` を既存D1へ追加適用します。既存テーブルの削除・置換は行いません。Workerの `global_fetch_strictly_public` フラグを有効にし、再アップロードでは `BACKUP_TOKEN_SHA256` のSecretを維持します。端末側はIndexedDB v2からv3へ新規ストアだけ追加します。公開後はアプリの再読み込みで更新を受け取れます。サイトデータ削除は不要です。

### v1.5.1 認証画面の修正

認証画面のフォーム送信で送信元が消える設定を修正し、Origin・端末セッション・一度限りの同意トークンの検証を維持します。CSPは同じ配信元と検証済みChatGPTコールバックだけを許可し、認証結果のリダイレクト時にはReferrerを送信しません。

### v1.5.2 受信時の確認を廃止

MCPから届いたレシピは、追加・保存の確認なしで一覧に登録します。端末への保存と受信済み記録は同じトランザクションで確定し、成功後にサーバーへ受信通知します。追加に失敗した本文は受信待ちとして保持し、編集中の別レシピを上書きしません。MCP権限は新しい下書きの追加だけのままです。
